# v1.0.0 Spec — 完成形の確定

Date: 2026-11-26
Status: draft（Issue が正本）
Base: v0.5.0 `release-0-5-0`（先行完成版: 全配布チャネル公開 + 実利用検証。
機能基盤は v0.4.0 `release-0-4-0` の package-manager distribution + 内包 adapter）

## 目的

skill-graph を「導入済み Agent Skills の発見・参照解決・根拠付き推薦・
利用観測」を、対応する全利用インターフェース（CLI / Hook / Plugin /
**MCP**）から一貫して提供する完成状態にする。v0.5.0 はこの完成形を
先行完成版として全配布チャネルへ正式公開し、v1.0.0 は v0.5.0 の
実利用・包括評価・最終監査を経た正式版とする。

## 完成形の要求

### 1. MCP server（新規・正式対象）

`skill-graph mcp` を stdio MCP server として実装する。単一バイナリの
一部であり、追加の配布成果物を持たない。

- transport: stdio（JSON-RPC 2.0 / MCP `initialize` lifecycle）
- tool surface は **read-only** に限定する（O02 の権限境界を継承）:
  - `recommend` — query / context / roots / max → CLI `recommend
    --format json` と同一 shape
  - `discover` — roots → CLI `discover --format json` と同一 shape
  - `resolve` — target / roots → CLI `resolve --format json` と同一 shape
- 書き込み・ファイル変更・network 取得・hook 有効化は行わない。
  package install だけでは何も有効化されず、MCP client への登録も
  各 client の設定で opt-in とする。
- event log / dedup state には触れない（観測イベントは hook/plugin
  経路の契約であり、MCP 呼び出しを擬似 session として混ぜない。
  MCP 経路の観測が必要になった場合は `observed_via` 拡張として別途
  設計する — 根拠は ADR-0005）。
- roots は tool 引数で明示指定可能。未指定時は CLI と同一の既定
  root 解決（`SKILL_GRAPH_ROOTS` → runtime 別既定 → cwd 系）を使う。
- fail-open: 内部エラーは tool error として返し、server は継続する。

### 2. 観測分析（observation-pilot の算出可能化）

`docs/specs/v0.3.0-observation-pilot.md` が定義した指標を、イベント
ログから直接算出する `skill-graph observe --summary`（または同等の
集計入口）を実装する。

- delivery / recall（load-grade のみ、`mention` 除外）/ conversion /
  不要ロード率 / timeliness / context 消費 を runtime・session 単位で
  集計し JSON で返す。
- recommendation→skill_load の join は同一 `session_id` かつ
  recommendation 以後の load-grade load のうち `recommended[]` に
  合致する最初のものとする（v0.3.0 observation-pilot の定義に一致。
  無関係の load が間に挟まっても conversion を損なわない）。
  各 load は高々 1 件の recommendation に対応付ける。
- 集計は read-only。イベント契約（`contracts/v1`）は変更しない。

### 3. 動的推薦の完成

既存の prompt-time / skill-load trigger に加え、session 内の推薦連続性を
持たせる。

- prompt mode で emitted recommendation がある場合、推薦した skill 名
  （名前のみ、prompt 本文は保存しない）を session state dir の
  `<sid>.recommended` に保持する。
- skill-load mode は loaded skill の依存推薦に、同 session で既に
  推薦済みの skill 名を `context` として渡し、session 内で一貫した
  推薦面を維持する。保持するのは公開 skill 名のみで、契約の
  non-persistence 境界（prompt 本文・コマンド・response 非保存）を
  破らない。
- `SKILL_GRAPH_HOOK_NOSTATE=1` では context も保持しない。

  ことを release 検証で確認する。

### 5. 既存環境の移行完遂

- v0.3.x install.sh 由来の配置・hook 参照を `adapter enable` で
  v0.4.x 形式へ移行（WSL2・macOS 実機）。
- Codex `/hooks` trust はユーザー操作として残し、迂回しない。
- pc-setup#242 merge 後に mise pin を正式管理へ戻す。
- dotfiles 側の adapter opt-in 状態の再現経路を文書化する
  （`adapter enable` は冪等なので runbook 化で足りる。dotfiles が
  hook 設定を直接管理しない境界は維持）。

### 6. deferred 項目の最終判定

| 項目 | 判定 | 根拠 |
|---|---|---|
| O01 永続キャッシュ | **不採用** | warm recommend p95 0.68ms・process p95 13.1ms（release, 500 skills。根拠: `docs/evidence/2026-11-25-c03-performance-benchmark.md`）で性能要件を充足。cache key 無効化・意味同値性の複雑さに見合う利益がない。MCP server も tool call ごとに in-memory graph を再構築し（cold discover+build ~7.7ms / 500 skills）、process 内キャッシュ・永続キャッシュのいずれも持たない。これにより常駐 stdio server でも SKILL.md の追加・更新・削除が次の呼び出しに即時反映される（#173 / 監査 I-01） |
| O02 MCP | **採用** | 本 spec §1。stdio・read-only・opt-in 登録 |
| Embedding | **不採用** | glossary + text search で eval（required_recall 1.0, forbidden 0）を充足。意味的曖昧さの残課題は dataset 拡張で対処し、外部モデル依存・runtime 依存を増やさない |
| グラフ DB / 常駐 service | **不採用** | in-memory resolver で対象規模（〜500 skills）を充足。永続化が必要な状態は event log のみで契約済み |
| I01 上流標準化 | **v1.0.0 対象外（判定確定）** | 実装・運用実績が前提条件であり、v1.0.0 時点で pilot 実績が不足。Skill Usage Event v1 contract と Agent Plugins v1.0.0 準拠 package は既に標準形で配布しており、上流提案は pilot データ蓄積後の別判断とする（先送りではなく前提条件未達の確定判定） |

### 7. 仕上げ

- experiment 用 `src/bin/x0*.rs` を `cargo install` / crates.io 同梱物から
  除外（`examples/` へ移動）。
- 公開契約（CLI JSON shape、event contract、adapter 状態機械、hook
  fail-open）の最終監査と `contracts/` schema 検証の CI 化。
- README を完成形（全インターフェース・MCP 登録例・観測分析）に更新。

## 非目標（v1.0.0 でも維持）

- Windows native 対応（WSL が対象）。musl libc バイナリ（glibc のみ）。
- 永続キャッシュ・グラフ DB・Embedding・常駐サービス（§6 の判定）。
- hook trust・権限境界の迂回。
- package install による暗黙の hook/MCP 有効化。
- prompt 本文・コマンド・tool response の永続保存。
