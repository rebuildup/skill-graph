## 指標定義（event → metric）

`skill-graph observe <path>` の出力 events を以下に写像する。
`recommendation` / `skill_load` は `session_id` と時系列近接
（同一 session で recommendation 発行後の最初の skill_load）で join する。

| 指標 | 定義 | 対応 eval spec 指標 |
|---|---|---|
| delivery | `recommendation` event で `emitted=true`（model に additionalContext/plugin injection が届いた）の割合 = emitted / 全 recommendation | 新規（推薦が届いたか） |
| recall (invocation) | load-grade detection（`file_read`/`path_reference`/`native_invocation`/`inferred`/`applied`、`mention` 除外）の `skill_load` / session | Invocation Recall |
| conversion | 推薦された skill が同 session 内で load-grade `skill_load` になった割合 = converted recommendations / emitted recommendations | 推薦→実ロード |
| 不要ロード率 | load されたが推薦に含まれなかった skill_load の割合（群比較で評価） | 不要ロード率 |
| timeliness | recommendation timestamp → 対応 skill_load timestamp の差分分布 | Timeliness |
| context 消費 | recommendation `emitted=true` あたりの件数・頻度（注入量の代理指標） | 追加 context 消費 |

`mention` は load 集計から除外（`SkillUsageEvent::counts_as_load` と同じ規則）。

### 集計（observe --summary）

session 単位 join 済みの funnel 指標は `observe --summary` が直接返す
（旧 jq 手順は `$recs[0].session_id` 固定参照で時系列 join がなく
誤りだったため撤去 — #225 G06）:

```bash
skill-graph observe ~/.claude/projects --summary
```

出力 field と本表の対応:

| 指標 | `observe --summary` field |
|---|---|
| delivery | `delivery_rate_pct`（= emitted_recommendations / recommendations） |
| recall (invocation) | `loads_per_session`（load-grade skill_load / session） |
| conversion | `conversion_rate_pct`（= converted_recommendations / emitted_recommendations） |
| 不要ロード率 | `unnecessary_load_rate_pct` |
| timeliness | `timeliness_ms`（p50/p95/max） |
| context 消費 | `context_consumption`（emitted_total / per-session avg・max） |
| 層別 | `by_runtime` / `by_session` |

生 events が必要な場合のみ `--format json`（`--summary` なし）を使い、
分析は `experiments/` の script で行う。

## パイロット設計

- **対象 runtime**: Claude Code を第1対象（transcript + hook の両経路が
  整備済み）。Codex は第2候補（Bash 分類経路あり）。OpenCode は plugin
  経路が live-verified core のため対象外（別途判断）。
- **期間**: 最低 2 週間 かつ群あたり 50 sessions を目標。release gate は
  「conversion 指標が算出可能」であり、190-session 規模の事前収集は
  要求しない（v0.2.0-evaluation の骨子を継承）。
- **群分け（A/B）**: 同一マシン・同一 corpus で交絡を抑えるため、
  **日単位の交互割当**を第一候補とする（例: 奇数日=有効、偶数日=無効、
  `install.sh --uninstall`/再 install で切替）。prompt hash による
  決定的割当は session 内一貫性の点で劣るため補助とする。
  層別: runtime・corpus 規模。runtime 間の直接比較はしない。
- **観測対象**: opt-in で `install.sh` 済みの開発者の実 session。
  transcript は `observe` が read-only で読む。イベントログの既定は
  per-user state root（`$XDG_STATE_HOME/skill-graph/events.jsonl`、
  無ければ `~/.local/state/skill-graph/events.jsonl`、HOME も不明な
  場合のみ `${TMPDIR}/skill-graph/events.jsonl` — #225 D06/G08）。
  パイロット期間中は `SKILL_GRAPH_EVENT_LOG` をユーザー指定の
  永続パスに向けるか、週次で `observe` 出力を分析 dir に保存する。

## プライバシー境界

- 保存するのは contract event のみ: prompt は SHA-256 hash、コマンド・
  tool response・会話本文は非保存（W02 契約）。
- transcript/DB の解析は read-only。分析 dir はユーザー指定パス
  （例: `~/skill-graph-pilot/`）で、リポジトリ・公開先には置かない。
- `SKILL_GRAPH_HOOK_NOSTATE=1` の no-save モードは pilot では使わない
  （イベント収集が目的のため）。

## 継続改善サイクル

1. **週次レビュー**: delivery / recall / conversion / 不要ロード率を
   群別・層別に集計。n が小さい間は信頼区間併記、有意差を主張しない。
2. **仮説 → dataset 還元**: 観測で見つかった miss（recall 低下）・
   false positive（不要ロード）を `evals/dataset/cases.jsonl` の case と
   して追加し、ranking/admission の改善仮説を立てる。W03 の glossary・
   admission・ranking の変更はこのケースで検証する。
3. **再測定**: 変更後の cohort で同じ指標を再集計し、効果量で比較。
4. **Issue 還元**: 改善が必要な場合は skill-graph Issue を起票
   （ranking/admission/glossary/adapter のいずれか）。
