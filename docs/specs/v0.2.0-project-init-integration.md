# v0.2.0 #56 — project-init との疎結合な統合設計

Date: 2026-11-25
Issue: #56
依存: #55（観測）が前提 — 統合評価は #57 の枠組みで行う。

## 結合方針: 共有規格のみ、相互依存なし

project-init（`rebuildup/project-init`）と skill-graph は**どちらも相手を
必須依存にしない**。統合点は Agent Skills の標準配置だけに限定する。

## 既に成立している整合

| project-init の配置 | skill-graph の discovery |
|---|---|
| `.agents/skills/`（repo canonical） | `$PWD/.agents/skills` + `~/.agents/skills` を既定 root に含む |
| `~/.agents/skills`（user canonical） | 同上 |
| agent 別 mirror（`.claude/skills` 等） | 同名 dedup / name collision 契約（C04/C05）で安全に処理 |

project-init が skill を `.agents/skills` に配置する限り、skill-graph は
**追加設定なしで発見できる**。これが v0.2.0 の統合の中核であり、これ以上の
密結合は不要。

## 統合として追加するもの（最小）

1. **adapter 有効化の推奨経路の文書化**: project-init で初期化した repo で
   skill-graph hook を使う場合の推奨は `adapters/install.sh --project`
   （`.claude/settings.json` / `.codex/hooks.json` への opt-in merge）。
   project-init 自体は hook を書き込まない — 書き込むのはユーザーが明示的に
   実行した install.sh のみ。
2. **`skills-lock.json` との関係**: lock は source/freshness metadata であり
   skill-graph の discovery 入力ではない。recommend の同名衝突検出は
   digest ベースで独立に機能するため、lock 形式の変更は要求しない。
3. **観測の接続**: #55 の `observe` は transcript を read-only で読むため、
   project-init 管理下のプロジェクトでも追加設定なしで動く。

## やらないこと

- project-init への skill-graph 同梱・自動 hook 注入（依存方向を作らない）
- `skills-lock.json` schema の拡張（lock の責務は upstream 管理 metadata）
- project-init skill の recommend への特別扱い（graph 上の通常 skill と同一）

## 検証

- fixture: `.agents/skills` のみを持つ project-init 風 repo で discover が
  skill を発見し recommend が機能することを確認（実コーパス評価 #54 で
  実質検証済み: dotfiles `.agents/skills` 20 skills を含む corpus で動作）。
- install.sh --project の merge が project-init 管理ファイル
  （AGENTS.md, skills-lock.json, .claude/settings.json 既存内容）を壊さない
  ことを #53 の roundtrip 検証で確認済み。
