## skill-graph binary の導入経路: pc-setup 管理の判断基準

分離案を採用する:

- **導入（binary provisioning）**: pc-setup の管理対象に**してよい**。
  条件は (a) 配布物が version 固定で再現可能（release archive +
  `sha256sums.txt`、または mise backend）、(b) `mise.global.toml` 等の
  既存 tool baseline に1エントリ追加するだけで済む、(c) 導入しても
  adapter は有効化されない（binary があるだけでは何も起きない）。
  現時点では release artifact が未整備のため、pc-setup 側の変更は
  v0.3.0 release 後に `rebuildup/pc-setup` へ Issue として切り出す
  （本 doc 末尾「切り出した Issue」参照）。
- **adapter 有効化**: pc-setup に**含めない**。`install.sh` の実行は
  project-init 実行後の user/project opt-in、または user が直接実行する
  運用とする。machine provisioning が project-local hook を黙って
  有効化すると「opt-in」契約（adapters/README.md）を破るため。
- **project-init**: skill-graph の導入・有効化を init 手順に**含めない**。
  project-init が生成する repo で skill-graph を使う場合の推奨経路は
  v0.2.0 doc 通り `adapters/install.sh --project` の手動実行のみ。

## dotfiles の skills-lock.json / skills CLI との整合

- `skills-lock.json` は skills CLI（vercel-labs/skills）が管理する
  source/freshness metadata であり、**skill-graph は一切読まない**
  （v0.2.0 doc の方針を維持）。recommend の同名衝突は digest ベースで
  独立に機能する。
- `keywords` の upstream 提案経路: skill-graph 側の組み込み glossary
  （W03, `src/search.rs`）は配布辞書であり、個別 skill の frontmatter を
  変更しない。標準 Agent Skills の `keywords` を充実させたい場合の
  提案先は **skill の upstream repo / project-init catalog** であり、
  skill-graph 内に skill 固有の語彙をハードコードしない。
  具体的な skill が不足を示した場合は、その skill を管理する repo に
  Issue/PR を切る（現時点で対象 skill は未特定のため Issue 化は保留）。

## 非接続点の確認

- skill-graph 単体で discover/search/recommend/resolve/observe/detect が
  全機能動作する（adapter 未導入でも CLI は完結）。`mise run check`・
  `tests/` が外部 repo なしで通ることを確認済み。
- project-init / dotfiles / pc-setup のいずれも skill-graph を必須依存に
  しない。本 doc は skill-graph repo 内の設計記録であり、相手 repo への
  変更は「切り出した Issue」のみ。
