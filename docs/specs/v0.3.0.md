# v0.3.0 Spec — ランタイム横断の利用観測と継続的改善

Status: draft（Issue が正本）
Date: 2026-11-25
Base: v0.2.0 `release-0-2-0` @ `d2e8a57`（リリース候補、main 未統合）

## 目的

v0.2.0 で3ランタイムの推薦経路を確立した。v0.3.0 の主目的は:

1. **ランタイム横断のスキル読み込み検出** — Codex に Skill tool がない
   ことを「検出不可能」の根拠にしない。ファイル読み込み・Bash 操作・
   既存 transcript・ランタイムイベントから、非汚染・低コストな観測を
   ランタイムごとに比較して成立させる。
2. **共通 Skill Usage Event への正規化** — ランタイム差分を吸収する
   統一イベント契約を定義し、observe/評価の入力にする。
3. **多言語推薦性能の改善** — `keywords` は任意の精度向上手段であり、
   標準 Agent Skills（独自メタデータなし）への対応を縮小しない。
   実コーパスでの言語横断 recall を改善する。
4. **実利用環境への配布・導入・更新・削除経路** — 対象 OS・ランタイムで
   検証済みの手順を整備する。
5. **疎結合な統合** — project-init / dotfiles / pc-setup との責務境界を
   維持したまま接続点を設計する。
6. **実運用観測と継続的改善** — #57 評価設計に基づくパイロット運用と、
   観測結果に基づく ranking/admission の継続改善。

## 非目標（維持）

- 永続キャッシュ・MCP・Embedding・高度なグラフ処理は、v0.2.0/v0.3.0 の
  実測で必要性が実証されるまで deferred を維持する。
- Hook の信頼確認・権限境界を迂回する恒久導入経路を作らない
  （`--dangerously-bypass-hook-trust` 等の実験用 bypass は恒久経路に
  持ち込まない）。
- 「推薦がモデルに届く」と「Invocation Recall が改善する」を混同しない。
  delivery と recall は別指標として評価する。
- release→main 統合・外部公開・恒久インストールは承認境界。

## Skill Usage Event 契約（W02 の設計入力）

ランタイム差分を吸収する最小イベント:

- `skill_load` — skill が実際に読み込まれた（name/path/digest, runtime,
  session_id, timestamp, source: hook|transcript|plugin）
- `recommendation` — 推薦を発行した（names, runtime, session_id,
  prompt hash — 本文は含めない）
- `prompt_submit` — プロンプト受理（hash のみ、本文非保存）

非機能要件: read-only または opt-in、会話全文・生ログを保存しない、
`${TMPDIR}` またはユーザー指定パスのみ、fail-open。

## 観測方式の比較軸（W01 の評価観点）

各ランタイムで以下を比較する:

- hook event（PreToolUse/PostToolUse/UserPromptSubmit/SessionStart）
- tool payload からの skill-load 推定（Bash `cat SKILL.md`、apply_patch、
  file read 系 tool の path 解析）
- 既存 transcript/rollout/DB の read-only 解析（observe 拡張）
- ランタイム標準イベント（OpenCode `tool.execute.*`、Codex rollout、
  Claude transcript）
- コスト（遅延・権限・汚染）と網羅性（見逃し率）のトレードオフ

## リリースゲート（v0.3.0 candidate、案）

- Skill Usage Event が全対応ランタイムで定義され、observe が集計可能
- 多言語 recall が標準スキル corpus で改善（keywords なしでも）
- 導入・更新・削除手順が対象環境で検証済み
- 実運用観測パイロットが開始可能な状態
- R01 相当の検証記録が現行 SHA に整合
