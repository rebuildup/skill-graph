# v0.4.0 Spec — CLI 内包 adapter とパッケージマネージャ配布

Date: 2026-11-26
ADR: ADR-0004
Issues: #100 (hook), #101 (adapter), #102 (opencode plugin), #103 (cleanup),
#104 (npm), #105 (homebrew), #106 (crates.io), #107 (README/migration),
#108 (mise/cargo docs)

## 目的

CLI・Adapter・Contracts を単一バージョン管理単位（skill-graph バイナリ）に
統合し、導入・有効化・更新・削除をパッケージマネージャ経路へ移す。

## `skill-graph hook`

```
skill-graph hook <claude-code|codex|opencode> <prompt|skill-load>
```

- stdin: ランタイムの hook payload JSON。stdout: hook response JSON
  （`hookSpecificOutput.additionalContext` 等）。exit code は常に 0
  （fail-open。内部エラーはイベントログにも残さず静黙）。
- `prompt` モード: `prompt_submit` + `recommendation` イベント発行、
  hit 時に `UserPromptSubmit` の additionalContext を返す。
- `skill-load` モード: tool payload の pre-filter（Skill tool または
  `SKILL.md` 参照を含む呼び出しのみ通過）→ `skill-graph detect` 相当の
  分類を Rust 内で実行 → `skill_load` イベント発行 → load-grade
  （`file_read`/`path_reference`/`native_invocation`/`inferred`/`applied`）
  のみ依存推薦を `PostToolUse` additionalContext で返す。
- イベント契約・ログパス・dedup・rotation・NOSTATE は v0.3.x の
  `skill-graph-recommend-hook` と同一（`contracts/v1`、
  `${TMPDIR}/skill-graph-events.jsonl`、`SKILL_GRAPH_EVENT_LOG[_MAX]`、
  `${TMPDIR}/skill-graph-hook-state`、`SKILL_GRAPH_HOOK_NOSTATE=1`）。
- pre-filter はバイナリ内で完結し、jq を要求しない。
- prompt 本文・コマンド・tool response は永続化しない（prompt は
  SHA-256 のみ）。

## `skill-graph adapter`

```
skill-graph adapter enable  <claude-code|codex|opencode> [--user|--project]
skill-graph adapter disable <claude-code|codex|opencode> [--user|--project]
skill-graph adapter status  <claude-code|codex|opencode> [--user|--project]
```

- `enable`: ランタイムのネイティブ設定へ hook/plugin エントリを冪等 merge。
  - claude-code: `settings.json` の `hooks.UserPromptSubmit` /
    `hooks.PostToolUse(matcher: Skill)`。
  - codex: `hooks.json` の `UserPromptSubmit` / `PostToolUse(matcher: Bash)`。
  - opencode: `opencode.json` の `plugins` に内包 plugin の materialize 先
    `file://` specifier を merge。plugin 本体は
    `~/.local/share/skill-graph/opencode-plugin/index.ts` へ書き出す
    （version 非依存パス。enable のたびに最新内容で上書き）。
- hook command は `<skill-graph の絶対パス> hook <rt> <mode>`。
  PATH 上の `skill-graph` を解決して埋め込む。`--bin <path>` で明示指定可。
  hook runtime で解決不能時はエラー（hook を中途半端に有効化しない）。
  opencode は plugin が runtime の PATH から解決するため、bin 解決不能時は
  warning に留め plugin は fail-open で待機する（`status` は broken を報告）。
- `disable`: 対象エントリのみ除去。group が空になれば prune、`{}` まで
  減ればファイル削除（v0.3.x と同じ復元意味論）。materialize した
  opencode plugin ファイルと `plugins` エントリを除去。
- `status`: enabled / disabled / broken（埋め込みパスのバイナリ不在）/
  legacy 検出を報告。
- legacy 移行: `enable`/`disable`/`status` は v0.3.x 形式
  （`skill-graph-recommend-hook` を含む command、`adapters/.../skill-graph`
  を含む plugin specifier）を marker 検出し、enable 時は同時に除去して
  新形式へ置き換える。dotfiles compose overlay の掃除も維持するが、
  対象は `SKILL_GRAPH_EXTRA_OVERLAY` で opt-in した path のみ
  （contracts.md「adapter の compose overlay」参照。固定 path は
  バイナリに埋め込まない）。
- PATH・shell rc・無関係な設定キーは変更しない。install は常に opt-in
  （package install だけでは hook は有効化されない）。

## パッケージング

- release workflow は per-target `skill-graph-<target>.tar.gz` +
  `sha256sums.txt` のみを成果物とする（adapters bundle・install.sh 廃止）。
- npm: `@rebuildup/skill-graph` metapackage +
  `@rebuildup/skill-graph-<platform>` optional deps 4種
  （linux-x64/arm64, darwin-x64/arm64）。release tarball からバイナリを
  そのまま同梱し postinstall download/build なし。musl・Windows は v1 対象外。
- Homebrew: `rebuildup/tap` に `Formula/skill-graph.rb`。OS/arch 別
  `on_*` url + sha256 で release tarball を参照。
- crates.io: `skill-graph` crate を publish（source build）。
- mise: `github:rebuildup/skill-graph` backend（既存）。pc-setup の
  `mise.global.toml` エントリはこの経路のまま維持。
- Agent Plugins package（`plugins/skill-graph/`）: `plugin.json` の
  `version` は **product release version（`Cargo.toml` / npm
  `package.json` と同一）を追跡する**。release 時に product version
  へ合わせて bump する運用とし、manifest 単独で先行・遅行させない
  （npm publish workflow が `plugins/skill-graph` を package 同梱する
  ため、不整合はそのまま配布物に出る）。現時点で `plugin.json` が
  product version とずれている場合は release 準備タスクとして修正
  する。

## 移行

- v0.3.x で導入済みの環境は `skill-graph adapter enable <rt>` 一発で
  新形式へ移行（旧 marker を自動除去）。
- `~/.local/share/skill-graph/<ver>/` + `current` symlink +
  `~/.local/bin/skill-graph` の旧レイアウトは package manager 管理下へ
  移行後に削除可能（`adapter status` が broken を報告しないことを確認して
  から）。
- mise shim / npm global bin / brew のいずれの絶対パスでも hook command
  として機能する（enable 時に PATH 解決したパスを埋め込む）。

## 検証要件

- `skill-graph hook` の入出力が v0.3.x shell hook とイベント契約・
  additionalContext 形式で一致すること（fixture diff）。
- `adapter enable → disable` が seeded config を復元すること
  （runtime×scope 全組合せ、legacy 混在ケース含む）。
- package 削除後も runtime が fail-open で動作すること。
- npm/bun/pnpm での install・pin・upgrade・uninstall 実測。
