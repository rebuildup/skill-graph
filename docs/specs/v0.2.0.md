# v0.2.0 Spec — 実運用適用と呼び出し性能評価

Status: draft（Issue #51–#57 が正本）
Date: 2026-11-25
Base: v0.1.0 `release-0-1-0` @ `80f8424`

## 目的

v0.1.0 は単一ランタイム（Claude Code）・合成タスク・n=1/cell の実験的初期
リリースである。v0.2.0 の主目的は次の2点:

1. **適用範囲の拡大** — 実際の開発環境で使えるランタイム・導入経路・
   project-init 連携を揃える。
2. **実運用による呼び出し性能の評価** — 推薦性能（dataset）と実際の
   Invocation Recall を区別したまま、実利用データで改善を検証する。

## 非目標（v0.2.0 でも維持）

- 永続キャッシュ・MCP Server・グラフDB・Embedding・常駐サービス
  （O01/O02 相当）は、v0.1.0/v0.2.0 の実測で必要性が実証されるまで着手しない。
- 呼び出し回数・ロード回数の増加自体を成功条件にしない。
- 標準 Agent Skills・project-init の正本構造を変更しない。
- release→main 統合・外部公開・恒久インストールは承認境界として維持。

## 評価の比較可能性（#57 の設計原則）

- v0.1.0 の live 結果は n=1/cell・単一モデル・合成タスクであり、統計的
  改善として扱わない。v0.2.0 では対照条件を固定した比較を設計する。
- 当初の 741 calls / 190 sessions 統計は E01 で元ログ未発見の
  「reported context value」であり、正解ラベル・比較基準には使えない。
  v0.2.0 では同等の規模の観測データを新規に集める設計とし、旧統計との
  数値比較は「参考値」としてのみ扱う。
- 指標の優先順位: Invocation Recall（必要スキルの実ロード）> 不要ロード率
  > timeliness > context 消費 > 成果物品質。呼び出し回数は副次指標。
- 交絡対策: 導入前後で作業内容・利用可能スキル・モデルが変わるため、
  ペア化・層別・期間正規化のいずれかを #57 で選択する。単純な前後比較を
  改善とみなさない。

## Adapter 共通契約（v0.1.0 から継承）

fail-open、session dedup、推薦なし無出力、no-save mode、PATH 不要、
状態/ログは `${TMPDIR}` 限定。ランタイム差分（hook event 名、payload
形状、context 注入経路）は各 adapter の evidence に記録し、エンジン層の
契約（`contracts/v1/`）は変更しない。

## リリースゲート（v0.2.0 candidate）

- 全 adapter が live 検証 evidence（verified scope 明示）を持つ
- 実コーパス性能が ADR-0002 目標内、または逸脱の根拠と対策が記録済み
- opt-in 観測で conversion 指標が算出可能
- 評価 Spec が承認されパイロット計画がある
- R01 相当の検証記録が現行 SHA に整合
